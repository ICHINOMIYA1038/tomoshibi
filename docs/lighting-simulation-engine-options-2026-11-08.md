# 照明シミュレーションの描画方式をどう選ぶか

確認日: 2026-11-08（JST）。対象は TOMOSHIBI の照明プレビューと照度計です。

## 結論

現行画面の限界には Three.js の描画方式が関係しています。まず実機の配光データを用いた比較ページを作り、その配光を演出画面のフレネル灯にも試験導入しました。画面の光の広がりと照度計は同じ IES データを参照します。画面の絶対的な明るさは舞台写真で校正していません。

開発の第一候補は、編集時の Three.js を維持し、高品質な静止画プレビューを追加する構成です。採用は比較結果で決めます。

## 試作前の実装で確認したこと

| 項目 | 現状 | 画面への影響 |
| --- | --- | --- |
| 器具の配光 | 描画は `SpotLight` の円錐状配光。照度計は独自の `beamIntensity()`。 | 同じ灯具でも画面と lux が別の分布になる。 |
| IES | `iesParser.ts` は IES ファイルを読み、配光曲線を表示する。描画と照度計はそのデータを参照しない。 | 実機の非対称配光やホリゾント灯の広がりを再現できない。 |
| 減衰 | 描画の `SpotLight` は `decay={1.7}`。照度計は距離の二乗で減衰する。 | 距離を変えた時の明るさが一致しない。 |
| 光の回り込み | 照度計は直接光のみ。画面も現在は `RenderPipeline` を使用しない標準描画。 | 反射光や柔らかい影を比較する基準がない。 |
| 材質と形 | 床、人物、背景は簡略化した模型。 | 光源を改善しても、人の顔や舞台美術の見え方に限界が残る。 |

これらは試作前の `src/scene/Beams.tsx`、`src/photometric/illuminance.ts`、`src/photometric/iesParser.ts` と [画質差の記録](lighting-quality-gap-2026-11-08.md)で確認しました。下記の測光配光の試験導入により、前の表の「IES 未使用」と「描画と照度計の配光が別」という点は、選択したフレネル灯について解消しました。照度計の数値は、実測との照合が終わるまで実機予測値として扱いません。

## C 言語や低レベル API で自作する場合

Three.js は WebGL / WebGPU の上で動く描画ライブラリです。独自の計算やシェーダーを書く余地があります。C を WebAssembly に変換した場合も、ブラウザでの GPU 描画は WebGL / WebGPU の API を通ります。[Emscripten の WebGL 対応](https://emscripten.org/docs/porting/multimedia_and_graphics/OpenGL-support.html)と[WebGPU 対応](https://emscripten.org/docs/porting/multimedia_and_graphics/WebGPU-support.html)がその経路を示しています。

| 自作する範囲 | 使い道 | 開発上の判断 |
| --- | --- | --- |
| C / WebAssembly で照明計算 | IES の補間、照度計、遮蔽判定を共通の数値計算にする。 | CPU 計算や外部ツールとの共用には有効。画面の光・影は別に実装する。TypeScript で速度が足りないか測ってから移す。 |
| Three.js 内の独自 GLSL シェーダー | 既存の舞台操作と 3D 模型を使い、IES の水平・鉛直配光、材質、影を描く。 | 最初の試作に適する。現行の `ShaderMaterial` に近い方式。灯具が増えた場合や間接光の計算には性能上の限界がある。 |
| WebGL 2 を直接使う独自描画器 | 描画パス、光源データ、影、色変換をすべて制御する。 | ライブラリ由来の制約を取り除けるが、3D 模型の表示、選択、カメラ、材質も自前で保守する。[WebGL 2 仕様](https://registry.khronos.org/webgl/specs/latest/2.0/)に従う。 |
| WebGPU と WGSL を直接使う独自描画器 | IES 配光と、GPU の並列計算による高品質な光のプレビューを作る。 | 多灯具の計算やパストレーシングに拡張できる。[WebGPU](https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API)は対象ブラウザによって利用可否が異なるため、WebGL 側の表示経路が必要。[WGSL 仕様](https://gpuweb.github.io/gpuweb/wgsl/)を参照。 |
| C / C++ 製の独自 CPU レンダラー | 写真に近い静止画をサーバーまたはローカルで生成する。 | アルゴリズムの自由度は高い。レンダラー全体の検証と保守が必要で、編集中の即時表示には向かない。既存の Blender / Radiance と画質・計算値を比較して判断する。 |

実装の境界は「舞台とシーンを編集する UI」「灯具の測光データ」「画像を描く処理」に分けます。最初の試作では UI と 3D 模型の操作を維持し、照明シェーダーを自作します。

別の WebGPU 描画器を試す場合は、同じシーンデータを別のキャンバスへ渡します。これで 2 種類の描画結果を同一条件で比べられます。

光の計算では IES の水平角・鉛直角から光度 `I(θ, φ)` を引き、直接光の照度を `I(θ, φ) × 入射角の余弦 ÷ 距離²` で求めます。画面側と照度計は同じ配光表を参照します。影、反射光、色、露出は別々に検証します。C や WebGPU を採用しても、この入力と検証は必要です。

## 比較実験の条件

目標は、**客席から見た舞台の明るさ・色・陰影・視線の集まり方を、実際の照明計画に近づけること**です。lux は照らされた面の値です。観客が見る明るさには、材質、面の向き、反射光も関係します。[Radiance の説明](https://www.radiance-online.org/learning/documentation/book/rwrextras/ch1/ch1.pdf/at_download/file)は、光源の測光データと輝度の計算を重視しています。

再現する条件は次の 5 つです。

1. **灯具**: 実機の配光、出力、調光時の色、アクセサリーを記録する。IES 配光ファイルだけでは、衣裳や肌に現れる色は決まらない。[Illuminating Engineering Society の TM-30](https://ies.org/products/technical-memorandum-ies-method-for-evaluating-light-source-color-rendition/)は光源による色の忠実度や色域の変化も扱う。ホリゾント灯は取付位置と隣の灯具との重なりも記録する。[ETC のホリゾント灯資料](https://www.etcconnect.com/webdocs/Fixtures/MyETCPhotometrics/Content/Cyc.htm)は、壁の寸法・設置距離・重なりから灯数と間隔を決めている。
2. **舞台**: 床、幕、壁、衣裳、肌、舞台セットの形と反射特性を揃える。単色の板や単純な人形だけで画質を判定しない。
3. **光の伝わり方**: 直接光、遮蔽、影、反射光を分けて確認する。ヘイズがある場面だけ、空気中に見える光を加える。
4. **表示**: 線形の光量で合成し、露出と画面への色変換を固定する。[Three.js の色管理](https://threejs.org/manual/pages/color-management.html)も、照明計算と画面表示で色空間を分けている。
5. **評価**: 客席から同じ位置・条件で撮った写真、測定点の lux、可能なら背景と顔の輝度を揃えて比較する。写真の露出とホワイトバランスを記録し、照明設計者が舞台としての違和感を評価する。

一般的な画面は実際の舞台の輝度範囲をそのまま表示できません。写真も肉眼の見え方とは異なります。写真との比較では露出・色変換を固定し、客席での印象は別に確認します。床の照度が均一でも、人物の顔が読めない、背景に山形のむらが見える、演出上必要な暗さが失われる場合は改善が必要です。

『花のしるし』から、床・人物・赤い布・背景が同時に見える場面を 1 つ固定します。実機データを取得できる前明かりとホリゾント灯を各 1 種以上選び、IES の角度別光度と器具の向きを共有データにします。灯具の出力、舞台寸法、材質、カメラ位置、露出を固定します。

各方式で次を記録します。

1. 灯具を 1 台ずつ点灯した時の床・背景・顔の見え方と、全灯点灯時のむら。
2. 同じ測定点の lux。実測値かメーカーの配光図がある場合は、その条件と照合する。
3. 客席視点の画像。基準写真が撮れる場合は、露出とホワイトバランスを揃えて比較する。
4. シーン切替と灯具移動の応答時間。編集操作が止まらないかを確認する。
5. 影の柔らかさ、人物・布の読みやすさ、背景の均一さを照明設計者が評価する。

実測値と基準写真が未入手なら、評価結果には「内部モデル間の比較」と明記します。数値が揃っても見た目が悪ければ、形・材質・露出を含めて原因を調べます。

## 比較ページの構成と次の試作

既存の舞台データを変更せず、比較ページを別パスに作りました。測光側では IES 配光と照度表示が同じ光度データを使います。その後、演出画面のフレネル灯にも同じデータを導入しました。次の試作候補は WebGPU の IES 表示と高品質プレビューです。同一視点で画質と速度を比べ、必要なら Blender Cycles を静止画の比較基準にします。

方式を決める基準は、実機に近い照度分布、舞台として納得できる見え方、シーン編集時の応答速度の 3 点です。

## 比較ページで分かったこと

`/lighting-lab/` に比較ページを作りました。『花のしるし』の舞台・役者・7 灯の位置と調光率を使い、円錐状の `SpotLight` とメーカー IES 配光による直接光を同じ客席視点で表示します。測光値は [ETC fos/4 Fresnel 10 Daylight Mid](https://www.etcconnect.com/products/entertainment-fixtures/fos/4-fresnel/documentation.aspx) と [Source Four LED CYC Daylight HD Series 2](https://www.etcconnect.com/Products/Entertainment-Fixtures/Source-Four-LED-Adapters/Documentation.aspx)の公開ファイルです。元のデモと実機は同一器具ではありません。

最初の試作では、デモの地明かりがビーム角 28°なのに、IES は半値角から求めるビーム角が約 60°の Flood 配光を使っていました。このため 1 灯でも右側の画面が舞台全体へ広がり、同じ条件の比較になっていませんでした。メーカー ZIP に含まれる Mid 配光は同じ測り方で約 28°です。地明かりを Mid へ変更し、旧 Flood 版の照度値と画像は破棄しました。

1 灯の実配置では、灯具が床を斜めに照らすため、床上の光は楕円に伸びます。輪郭は舞台セットの端でも切れます。診断用に同じ Mid 配光の灯具を床の真上へ仮置きする表示を追加しました。真上の視点では、測光側も円形に広がることを確認できます。[実配置の画像](lighting-reviews/lighting-lab-one-oblique-2026-11-08.png)と[垂直テストの画像](lighting-reviews/lighting-lab-one-vertical-2026-11-08.png)を保存しました。この仮置きは演出プランの灯具配置には保存しません。

背景は元の 3 灯と、合計出力を変えずに 6 灯へ分けた配置案を選べます。Mid 配光に変更した後の背景中段の測定点は、下手・中央・上手の順に 3 灯が 19.4 / 30.2 / 19.4 lux、6 灯案が 19.3 / 23.1 / 19.3 lux でした。**中段の左右差は小さくなりましたが、背景下部の暗い山形は残りました。** 床は 173.1 / 81.6 / 137.3 lux で、地明かりの均一さにも課題があります。[3 灯の画像](lighting-reviews/lighting-lab-three-cyc-2026-11-08.png)と[6 灯案の画像](lighting-reviews/lighting-lab-six-cyc-2026-11-08.png)を保存しています。

この比較は測光データの使い道を確かめる試作です。CYC の最大光度方向をデモの狙いへ合わせていますが、実機の取付角度は未確認です。人物とセットの形・材質は簡略化しており、反射光と正確な影も含みません。画面の明るさは現場写真に校正していません。したがって、現在の画像と lux は**実際の舞台の再現結果ではありません**。

### 舞台写真を使った見た目の確認

対称なスポットライトを光軸に垂直な面へ当てれば、光の輪郭は円形です。床を斜めに照らすと楕円に伸び、セットや舞台面の端でも切れます。地明かり全体の品質は、複数灯を重ねたときの床・俳優・背景の見え方で判断します。比較ページでは複数灯の組合せを先に表示し、1 灯と消灯は診断用の折りたたみメニューへ移しました。

ページには、別作品の舞台写真を 2 枚入れました。どちらも画面で切り替えて見られます。

| 写真 | 見る点 | 出典と利用条件 |
| --- | --- | --- |
| 『そして誰もいなくなった』（Monomoy Theatre、2013） | 暖色の明かりが舞台全体と複数の俳優をどう見せているか。床の明暗と顔の読みやすさ。 | [Wikimedia Commons](https://commons.wikimedia.org/wiki/File:%22AND_THEN_THERE_WERE_NONE%22_-_a_play_during_its_performance_on_the_stage.jpg)。写真クレジットは Heather Jessup、公開者は SarahSierszyn。[CC BY 2.0](https://creativecommons.org/licenses/by/2.0/)。掲載画像は横幅 1,280 px に縮小。 |
| 『Only A Girl』（2021） | 赤い背景の連続した色、俳優の輪郭、床に残る光の形。 | [Wikimedia Commons](https://commons.wikimedia.org/wiki/File:Only_A_Girl,_a_theatre_production_by_Lindsey_McAlister_(2021).jpg)。撮影者 BJCHK。[CC0](https://creativecommons.org/publicdomain/zero/1.0/)。掲載画像は横幅 1,280 px に縮小。 |

写真には照明器具の機種・位置・調光値と舞台材質の情報がなく、『花のしるし』とは別の舞台です。したがって、これらは**見た目の参考**であり、同じピクセル値や lux を目標とする校正データではありません。赤い背景の写真では床に光の形も見えます。円形が少しでも見えたら失敗とせず、俳優の可読性と意図した明暗を含めて判断します。

写真と現在の比較画面を見比べると、背景下部に残る暗い山形と、人物の平板な見え方が大きな違いです。まず背景灯の向き・間隔・重なりを検証し、人物の材質、影、反射光を加えて確認します。灯数だけを増やしても山形が消えないことは、6 灯案の画面でも確認できました。

次は『花のしるし』の灯具の取付角度と実演写真を揃え、背景の上下方向と人物の顔を照合します。その条件が揃ってから、描画方式の変更が必要か判断します。

## 演出画面への試験導入

試作サイトの `/mock/` では、フレネル灯と背景灯を選ぶと「配光」を切り替えられます。『赤鬼｜測光配光の照明試作』の各シーンで、地明かり 5 灯には ETC fos/4 Fresnel 10 Daylight Mid、背景灯 3 灯には ETC Source Four LED CYC Daylight HD Series 2 の IES データを適用しました。既存の保存プランは自動変更しません。

3D 表示では IES の角度別光度から投影テクスチャを作り、照度計は同じデータから測定点への直接光を計算します。灯具の位置、狙い、調光率は両方に反映されます。フレネル灯のズームは 28° の実測配光を角度方向に伸縮した近似です。28° 以外の配光を実測したものではありません。

初回の導入では地明かり 4 灯だけを変えました。画面で目立つ背景の山形は、元の背景灯 3 灯と、背景まで届く前明かり 3 灯によるもので、ほとんど変わりませんでした。背景灯に測光配光を適用し、前明かりの狙いと角度を役者に合わせて修正しました。修正後の『浜に現れた影』では背景の 3 つの白い山形が消え、青い帯状の明かりになりました。前明かりは実測データのない狭角器具の近似です。

[同じ客席視点での変更前後](lighting-reviews/mock-measured-before-after-2026-11-08.png)を保存しました。左が地明かりだけを変更した状態、右が背景灯と前明かりも修正した状態です。

投影テクスチャを使う灯具が増えると、端末の GPU が扱えるテクスチャ数を超えて画面が黒くなることがありました。演出画面では端末の上限に合わせて影を計算する灯具を絞ります。投影テクスチャ 8 枚を使う今回のデモでは、テクスチャ上限が 16 枚の端末で影を計算する灯具は 4 灯です。上限が低い端末では投影テクスチャの使用数も絞ります。その場合、3D 表示の配光は一部の灯具で近似に戻るため、照度計との一致は対象灯具に限られます。

単灯で床を照らした確認では、客席視点の光は斜め入射により楕円に見え、真上からは円に近い広がりでした。床の端や舞台セットの影で輪郭は途切れます。デモのフレネル灯と背景灯以外は従来の近似配光です。

### 床の光だまりを減らした再調整

『浜に現れた影』では、床中央が暗く、前明かりと赤鬼の輪郭光が足元に強い光だまりを作っていました。地明かりを 4 灯から 5 灯へ増やし、各フレネル灯の広がりを 44° にしました。手前の 2 灯を左右 3.5 m、奥の 2 灯を左右 3 m に向け、中央の 1 灯で手前中央を補います。前明かりは 19° 型の狭角器具に替えて出力を下げ、赤鬼の輪郭光も狭角器具に替えて弱めました。浜の床面は薄く広げ、厚い平台のように見える前縁を取り除きました。

床の測定値は、場面の中央 45 点（幅 -4～4 m、奥行 -5～-1 m、床上 0.1 m、各点間隔 1 m）で、**地明かりだけ**を点灯した計算値です。変更前は 10 パーセンタイルが 43.0 lux、90 パーセンタイルが 171.1 lux、比は 3.98 でした。変更後はそれぞれ 82.4 lux、115.4 lux、1.40 です。平均は 107.9 lux から 99.0 lux へ下がりました。44° の広がりは公開 IES の角度分布を拡大した近似で、44° 設定の実機を測った値ではありません。測定値には舞台セットの遮光、床材の反射、カメラ露出、ほかの灯具の光を含みません。

[客席視点の床](lighting-reviews/mock-floor-five-fresnels-2026-11-08.png)と[6 シーンの確認画像](lighting-reviews/mock-floor-six-scenes-2026-11-08.png)を保存しました。Chrome のローカルプレビューで 6 シーンとも 3D 画面が表示され、JavaScript の実行時エラーは出ませんでした。役者用の明かりが床や背景に落ちる部分は残ります。実際の舞台写真との明るさ・色の校正は未実施です。

`/lighting-lab/` の 7 灯比較は、調整前のプランを `lighting-lab/data/akaoni-study-baseline.json` に固定しました。比較ページの測定点と画像を、新しい 5 灯のプランで上書きしないためです。

3D 表示には画面用の光量係数と露出・トーンマッピングが入ります。照度計は IES の光度から lux を計算するため、画面のピクセル値を lux に直接換算できません。光の広がりは共通のデータになりましたが、絶対的な明るさ、材質の反射、影、色は実舞台と照合していません。デモの既存灯具を実機 ETC 製品として記録するものでもありません。
