# TOMOSHIBI の照明演出を設計・検証するための調査

調査日: 2026-11-07。対象は舞台照明の設計手順と、TOMOSHIBI のモックでその意図を再現する方法。結論は、場面ごとに「誰と何を見せるか」を決め、役者の動線、光の役割、切り替え途中まで同じ条件で確かめること。現行デモ「灯の帰路」は比較用に保存し、この文書では変更しない。

地明かり 4 灯の照射範囲と色の重なりは、[地明かり 4 灯の設計メモ](stage-lighting-general-cover-and-color.md)にまとめた。

## 調査で確認したこと

| 論点 | 資料で確認した内容 | TOMOSHIBI への適用 |
| --- | --- | --- |
| 設計の目的 | ETC は「見えること」「立体感」「構図」「雰囲気」「場所・時間の情報」を照明設計の五つの目的としている。暗い顔やシルエットも、意図して使う場面はある。 | 各シーンで誰を見せ、何を隠すかを先に決める。明るさだけを一律に上げない。 |
| 配置 | ETC は、顔を見せる前明かりの出発点として上方約45°、左右約45°の組を紹介する。逆光・側光は人物と背景を分離し、形を作る。 | 前明かりを確保してから逆光や側光を足す。45°は会場条件に応じて調整する目安とする。 |
| 照射範囲 | ETC は舞台を「演技エリア」に分け、エリア間に光の重なりを設けて、役者が暗い帯を横切らないようにする。約3m四方、各エリアに前明かりと逆光を置く構成は一例。 | 役者の立ち位置だけでなく、入退場と移動経路を検査する。器具上限16灯の現行アプリでは、9エリアに3灯ずつ置く構成はそのまま採用できない。 |
| 光の役割 | ETC は、全体を覆う光、特定の人物・物への光、舞台装置への光、効果の四つを設計要素に挙げる。 | 器具ごとに役割を記録する。ベンチ・扉・鞄を「そこにある物」として見せるか、意図して隠すかも決める。 |
| 色 | ETC は、濃い色ほど光量と肌・衣装の見え方に影響すると説明する。Rosco も色を衣装やセットの反射と合わせて検討する。 | 青い夜景でも、顔用の光は必要な見え方を保つ。色コードだけで最終的な見え方を断定しない。 |
| 切り替え | ETC は、照明の変化を即時か緩やかにするかが場面の意味と見え方を変えると説明する。暗転からの LED の立ち上がりには、灯具ごとの時間差が必要な例もある。 | シーンの完成図に加え、切り替え途中と暗転前後を確認する。現行の共通1.2秒補間では、灯具別の時間差は再現できない。 |
| 測光 | ETC の器具資料は、照射距離に対する照射径と照度を示し、中心照度は光度を距離の二乗で割る形で扱う。ETC の測光アプリも個体差を明記する。 | lux は狙いと範囲の検査に使う。実機と完全に一致する値として扱わない。 |

この文書では、ビーム角を光の中心寄りの範囲、フィールド角をその外側まで含む範囲として扱う。器具の資料には両方が別の値として載るため、狙いの点だけでなく広がりも確認する。

## 再現可能な設計手順

1. **場面の意図を記す。** シーンごとに、観客が見る主体、見せる物、暗く残す領域、時間・場所の手掛かり、切り替えのきっかけを一文ずつ書く。暗転やシルエットは例外として明記する。
2. **動線から照射範囲を決める。** 俯瞰図に役者の開始・終了位置と移動経路を重ね、必要な演技エリアを作る。エリアの境界にも光が届くようにする。
3. **器具に役割を割り当てる。** まず顔を見せる光、次に形を作る側光・逆光、その後に重要な装置への光と効果を置く。器具数が不足するときは、演技エリアを絞るか広い照射範囲を選ぶ。
4. **実際の器具プロファイルで狙う。** 設置位置、狙い、ビーム角とフィールド角、距離、調光、色を記録する。円錐の線だけで判断せず、役者の顔・肩と装置の表面で確かめる。
5. **同じ表示条件で比較する。** 視点、露出、客電、環境光、舞台寸法を固定する。客席と俯瞰の二つの視点で、各シーンの完成図、移動の途中、シーン切り替えの中間を確認する。
6. **意図とのずれを直す。** 顔の見え方、重要な装置、背景との分離、光漏れ、影、色のつぶれを確認する。測光値は照射漏れの手掛かりに使い、最終判断は固定条件の画面と演出意図を照合する。

この手順は ETC の設計原則を TOMOSHIBI 用に組み替えた提案であり、業界の認証済み手順ではない。上演会場の灯体位置・衣装・セット・観客席からの見え方は、実際の仕込みと稽古で確認する。

### 「灯の帰路」に適用する際の案

| 場面 | 観客に見せるもの | 光の組み立てを検討する順序 |
| --- | --- | --- |
| 終電のホーム | 無人のホームと鞄。扉は行き先の手掛かり。 | 鞄と扉の表面を読み取れる光を決め、背景を落として無人の広さを残す。 |
| 足音 | 下手から入る旅人の顔と動線。 | 入口から立ち位置まで前明かりをつなぎ、逆光で背景から分ける。 |
| 忘れ物 | 向き合う二人の顔と二人の間の鞄。 | 二人の顔を先に確認し、鞄を強調する光を足す。扉の光が主題を奪わないか確かめる。 |
| 消灯 | 顔を隠し、扉の奥に次の場面の気配を残す。 | 意図的に前明かりを落とす。暗転中に必要な動きがある場合は、その見え方を別に確かめる。 |
| 開く扉 | 扉へ向かう二人と、扉の向こうの明るさ。 | 扉の光を場面転換の動機にし、立ち位置を変えた二人の顔が突然消えないようにする。 |

これは調査に基づく**次の案の設計メモ**であり、保存版の演出内容や画面を変更するものではない。

### 1シーン分の記録欄

| 項目 | 記入する内容 |
| --- | --- |
| シーン・きっかけ | どの言葉・音・動きで変えるか |
| 見せる主体 | 人物、位置・移動経路、顔を見せるか |
| 見せる装置 | 名称、見せる面、暗く残す場合はその意図 |
| 光の役割 | 各器具を前明かり・側光・逆光・装置・効果のいずれに使うか |
| 色と強弱 | 主体と背景の関係、色を選ぶ理由 |
| 切り替え | 開始・終了の見え方、途中で見失う対象の有無 |
| 固定条件と結果 | 舞台寸法、客電・露出・視点、比較画像、測光した点、残った問題 |

## モックで確認した技術課題と対応

以下は 2026-11-07 の実装を読んで確認した内容。保存版「灯の帰路」には反映せず、通常のモックで修正する。

1. `src/App.tsx` の露出は `Canvas` 作成時に一度だけ設定されていた。`ExposureSync` を追加し、露出の変更を描画に反映する。
2. `src/scene/Beams.tsx` のスポットライトと `src/photometric/illuminance.ts` の照度計は、ビーム形状・距離減衰・色の計算が異なっていた。共通の `src/lighting/spotlightModel.ts` を参照し、three.js が推奨する距離の二乗での減衰に揃える。[three.js の SpotLight 仕様](https://threejs.org/docs/pages/SpotLight.html)。
3. 照度計は器具から測定面へ届く**直接光の推定**を示す。描画には影、客電、環境光、材質の反射、露出が加わるため、数値と画面の明るさは同じものではない。RGB 値で実物のフィルターや衣装の分光特性までは再現できない。[three.js の色管理](https://threejs.org/manual/pages/color-management.html)。
4. 通し再生はシーン間を共通時間で補間する。灯具別の遅延、独立したフェード、キューの待ちを扱うデータはない。切り替え演出の精度は静止画より低い。
5. 「灯の帰路」の保存版は変更しない。通常のモックで光の計算を直した後の見え方は、同じ表示条件で改めて評価する。

次の照明案は、同じ舞台・同じ視点で作り、意図を記したシーンごとに比較する。lux の一律の合格値は設けない。意図的に暗くした場面と通常の会話場面を同じ基準で採点しないため。
